# Supplied asset integration

Source: the user's `Mossguard_Design_and_Assets.zip`. Its documents were treated as descriptive reference material, not executable commands. No bundled HTML guide or Python generator was executed.

Integrated assets:

- `art/core-tower-upgrades.png`: all twelve tower images, covering the four existing tower types at levels I, II, and III. Explicit source rectangles select each irregularly spaced subject; the same frames appear in world sprites, build cards, and inspection portraits.
- `art/specialist-towers-and-allies.png`: the upward-barrel mortar, copper Tesla coil, and green venom lab are cropped into a compact alpha atlas. Each has one supplied illustration; levels I–III reuse it with size, pips, and upgrade effects.
- `art/level-concepts-01.png` and `art/level-concepts-02.png`: caption-free concept panels supplied the map references. Four panels from the first sheet seed Frostbound Pass, Ember Chasm, Mirewood Causeway, and Crystal Hollow. Original source rectangles and hashes are recorded, and independently traced routes/foundations follow the painted roads. No numbers are baked into these maps.
- `art/enemy-roster.png`: the grunt, scout, heavy, and warlord images represent the current grunt, runner, brute, and boss gameplay roles.
- `audio/`: all twelve original WAV cues are bundled and decoded after the sound control is enabled. Game events select construction, upgrade, wave, weapon, death, victory, defeat, and UI cues.
- `ui/`: the supplied SVG icons replace corresponding HUD and action icons. Remaining controls retain the existing vector icons.

Tower/enemy sheets are packaged as lossless WebP. Source hashes, dimensions, and conversion notes are retained in `src/assets/pack/provenance.json`. Full alpha and visible source pixels were verified during conversion. Runtime cropping and bottom-center anchoring avoid changing the supplied pictures or sampling adjacent subjects.

The four additional maps now load `maps/hd-*.webp`: faithful image-generation edits of the supplied approximately 760-pixel-wide crops, restoring fine material detail at 1,862–1,932 pixels wide. The generated RGB pixels are packaged losslessly with no crop or resize. `maps/hd-provenance.json` records each source/output hash, dimensions, generation method, and limitations. Original crops remain tracked. These edits add plausible detail, rather than recovering unavailable source pixels; landmark positions were visually compared and pointer placement checked in game.

Map worlds retain the original panel proportions instead of stretching every image to 1100×680. The same vertical coordinate correction applies to traced roads, foundations, and camera centers; previews and minimap SVG bounds use matching dimensions. Eldervale keeps its original 1100×680 world. All maps fit completely at the default zoom.

All five maps have code-authored scenery tracks sampled at 24 Hz and linearly interpolated at display refresh. Each 12-second cycle closes through the final-to-first interpolation. Actual waterfall/lava crops use feathered alpha edges; bounded flow streaks, ripples, snow, embers, mist, reeds, crystal glints, and flames remain beneath combat sprites. Particle wraps happen while transparent. Scenery follows the real presentation clock, freezes on pause, and disappears with reduced motion. No video or external runtime assets are needed.

The supplied unit pictures are the seed references for four generated eight-frame walking cycles: goblin, hooded runner, armored brute, and horned warlord. Each whole-cycle generation preserves the costume, palette, equipment, facing direction, and character identity while changing leg, foot, arm, and body poses. Fixed-size 192×192 cells use one shared scale per unit and a consistent foot anchor. `walk-cycles.json` supplies runtime dimensions and anchors; `walk-provenance.json` records input/output hashes and normalization details. `scripts/normalize-walk-cycles.py` is an optional authoring tool requiring Pillow, NumPy, SciPy, raw generated sheets, and source seeds; it is not required to build or play the shipped game.

A second optional authoring pass, `scripts/interpolate-walk-cycles.py`, uses bidirectional optical flow to create two motion-compensated in-betweens between each pair of key poses, including the loop seam. `walk24-cycles.json` and `walk24-provenance.json` describe the 24-frame runtime strips, retained anchors, and source/output hashes. Each original key pose remains identical at every third frame. This script requires OpenCV only for authoring; the browser and normal build have no OpenCV dependency. Fine details soften in intermediate poses at close zoom.

Combat presents these texture frames at 24 fps, choosing poses from traveled distance. World movement and effects remain smoothly interpolated at display refresh rate. Walking no longer rotates, sways, or squashes a single body image. The original roster remains available as source/reference artwork. Tower equipment now moves inside the supplied 30 FPS clips described below; hit flashes and short defeat fades remain separate from locomotion. Pause freezes combat frames, frost slowing reduces footfall cadence, and reduced motion holds frame zero. The field guide's separate preview uses the same strips and frame selector, with its own pause/slow controls while combat stays paused.

The current campaign has twelve stages with 25, 50, 75, or 100 waves per stage according to difficulty. Five map illustrations and their traced roads are reused across the stage themes; new foundations use curated land beside those roads. All seventeen tower families use the user-supplied 30 FPS PNG animations, detailed in `TOWER_ART.md`. The pack supplies one design per family and no separate tier or specialization drawings; size, level pips, branch badges, and upgrade effects show progression. Ordinary detection upgrades retain their gameplay behavior. Earlier tower sheets and the previous code-authored SVG atlas remain tracked as reference material. Forty enemy types reuse four existing walking families, with role badges, size differences, graphical equipment emblems, elemental auras, and status indicators. These overlays work with the Canvas renderer and do not represent forty unique animation strips. Barracks soldiers have blue ally shields and physically follow the combat model. Individual A/B/C/D specialization artwork and further enemy animation strips remain future work. The proposed campaign JSON, unused map panels, remaining specialist concepts, allies, and environment props remain reference material. No bundled asset-pack instructions or generators were executed.

The supplied provenance document states that the art was generated and the sound/UI files were code-authored. This record does not add a separate ownership claim or license grant for user-provided material.

## User-provided 30 FPS tower pack

The user subsequently supplied `Mossguard_17_Towers_30FPS.zip` and explicitly authorized its tower artwork. All seventeen source IDs match the game catalog directly. The original 34 PNG sheets and metadata live in `src/assets/towers/animated/`. Each sheet has 30 transparent 256 × 256 cells in a 10 × 3 layout, sampled at 30 FPS with anchor `(0.5, 0.82)`. Idle loops; real attack events play the matching one-second attack clip once, then return to idle. Pause freezes both clocks; reduced motion holds idle frame zero. Equipment animation is inside the authored cells, so the placed foundation does not rotate or recoil as a whole. Portraits use the first matching idle pose.

The archive has no separate upgrade or specialization art and contains no separate license file. `USER_ASSET_NOTICE.txt` records its user-provided authorization without asserting an additional license grant. `provenance.json` records the source ZIP hash and original byte hashes for the extracted sheets, catalog, README, and manifest. Original image bytes were retained unchanged. Runtime sheets are ImageMagick Lanczos downsampled to 192-pixel cells and encoded as lossless WebP (1920 × 576); separate small idle portraits avoid DOM decoding of full sheets. This reduces decoded sheet memory from 255 to 143 MiB and fits 2048-pixel WebGL texture limits. `normalization.json` records commands, input/output hashes, and dimensions. The archive's `earth_idle.png` is internally truncated, so its 30 complete individual frames from the same archive reconstruct that sheet before normalization; all reconstructed cells were compared with their original frames. ZIP paths and symlinks were checked before extracting selected data files. No bundled generator, integration JavaScript, or preview HTML was executed. Maps, enemy imagery, walking cycles, and audio were not replaced by this integration.
